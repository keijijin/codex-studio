## 1. インストールと起動

### 開発実行

```bash
pnpm install
pnpm dev
```

### パッケージ済みアプリ

GitHub Releases のインストーラ（macOS / Windows / Linux）を利用します。  
手順の詳細は [docs/release.md](../release.md) を参照してください。

---

## 2. 最初のセットアップ

1. アプリを起動する
2. **Open Folder** でプロジェクト（ワークスペース）を開く
3. **設定** を開き、LLM を登録する

| プロバイダ | 設定 |
|-----------|------|
| OpenAI | API キー + モデル |
| Anthropic | API キー + モデル |
| xAI (Grok) | API キー + モデル（例: `grok-4.5`）。環境変数 `XAI_API_KEY` も可 |
| Ollama | Base URL（既定 `http://localhost:11434`）+ ローカルモデル |

環境変数 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `XAI_API_KEY` / `OLLAMA_BASE_URL` も利用できます。

4. 右側 **AI Chat** で Ask または Agent を選んで質問する

---

## 3. 基本操作（IDE）

### 3.1 エディタ

- Explorer からファイルを開く
- `.md` はプレビュー / 編集を切り替え可能
- 保存: macOS `Cmd+S` / Windows `Ctrl+S`
- タブをすべて閉じる: macOS `Cmd+Alt+W` / Windows `Ctrl+Alt+W`

### 3.2 検索・ターミナル

- サイドバー **Search** でワークスペース横断検索（ripgrep）
- 下部パネルで組み込みターミナル（ログインシェル相当の環境を起動）

#### Agent Shell と環境

- Agent の **Shell**（および Hooks の shell）は、環境に応じてプロファイルを自動読込します（`~/.bash_profile` / `~/.zshrc` / PowerShell `$PROFILE` など）。コマンド前に `source` を付ける必要はありません
- **ファイルに残る認証**（例: `oc login` → `~/.kube/config`）は、プロファイル読込後の Agent Shell からも利用できます
- **そのターミナルだけで `export` した変数**やセッション固有の環境は、ターミナルパネルの **「環境を Agent に同期」** で Agent Shell に渡せます
- 恒久的な上書きはワークスペースの `.codex/agent.env`（`KEY=VALUE`）に書けます
- 詳細・優先順位・セキュリティ注意: [シェル環境と細かい機能メモ](../11-シェル環境と細かい機能メモ.md)

### 3.3 Ask / Agent

| モード | 用途 |
|--------|------|
| **Ask** | 質問・説明。`@ファイル名` で添付可 |
| **Agent** | 調査・編集・Shell。ツールを使って作業 |

Agent でファイルを書くときは、既定では **承認ダイアログ** で Diff を確認してから適用します。

## 4. 設定（安全と品質）

設定画面の主な項目です。

| 項目 | 説明 |
|------|------|
| 権限プリセット | **readonly**（調査のみ）/ **coding**（通常開発・承認あり）/ **yolo**（全自動）。詳細はカテゴリ個別でも調整可 |
| YOLO モード | ON で書込・Shell を承認なし実行（危険。信頼できる環境のみ）。プリセット `yolo` と同義に近い |
| Permission | 読取 / 編集 / Shell / ネットワーク / メディアごとに `allow` / `ask` / `deny` |
| 既定 Persona | 未指定時に使う声・方針（`/persona` で上書き可） |
| モデルルーティング | `固定` / `フォールバック` / `Auto`（下記） |
| 最大イテレーション | Agent のツールループ上限（既定 100） |
| Compact 閾値 | 履歴の推定トークン超過で自動圧縮（既定 40,000） |
| Ask / Agent 最大出力トークン | 1 回の完了トークン上限（コスト爆発の防止） |
| 日次予算（USD） | 推定課金が上限を超えると送信をブロック（0 で無制限、既定 $5） |
| プロンプトキャッシュ | Anthropic などで system をキャッシュ対象にする |
| 使用量ログ | `usage.jsonl` にトークン・レイテンシ・推定課金を記録 |
| 並列 Subagent 上限 | `Task` の同時実行数（1〜8） |
| Auto Memory | Agent 完了後に memory へ要約追記（オプトイン） |

### 4.1 モデルルーティング（マルチモデル）

既定は **固定**（設定したプロバイダ・モデルのみ）です。**Auto** にすると、複雑度・推定トークン量に応じて **課金最適化の階層ルーティング** を行います（OpenAI / Anthropic / xAI / Ollama）。

| モード | 挙動 |
|--------|------|
| 固定 (Fixed) | 既定モデルのみ（接続失敗時はフォールバック候補も試行） |
| フォールバック (Fallback) | 既定で開始し、429・接続失敗などで次の候補へ自動切替 |
| Auto | タスクを分類し **lite → standard → premium** で最適モデルを選択。失敗時は上位へ昇格 |

#### Auto の階層（目安）

| ティア | 用途 | 例（カタログ既定・自動更新あり） |
|--------|------|----------------------------------|
| lite | 短い質問・探索のみ・リネーム等の小修正 | **Grok 優先** → GPT nano / Haiku |
| standard | **Agent の通常実装・修正（既定）** | **Grok 4.3 優先** → GPT mini / Claude Sonnet |
| premium | 強い複合シグナル時のみ（分散設計+RCA 等） | Claude Opus 優先 → GPT-5.5 / Grok 4.5 |

単発の「修正」「実装」「migration」だけでは premium になりません。ルーティング理由に `rule`（例: `agent-default→standard`）が付きます。

モデル ID は各プロバイダの API 一覧から **約 24 時間ごと**に自動更新され、`~/Library/Application Support/codex-studio/model-catalog.json` にキャッシュされます。

**クイック切替**: AI パネル上部の **Fixed / Fallback / Auto** ボタンで即座に切り替えできます（ストリーミング中は不可）。

**フォールバックチェーン**: 設定画面でルーティングが Fixed 以外のとき、候補の順序・プロバイダ・モデル ID・最大試行回数を編集できます。「既定に戻す」で初期チェーンに復元します。

注意:

- API キー未設定のプロバイダはスキップされます
- Agent で **ツール実行が始まった後** はフォールバックしません（副作用回避）
- CLI: `--routing fixed|auto|fallback-only`
## 5. エージェント拡張（Phase A〜D）

### 5.0 Personas AI（声と優先順位）

Rules（規範）・Skills（手順）とは別に、**口調と優先順位**を固定する Persona を使えます。選んだ Persona は**セッションに固定**され、以降の Ask / Agent に引き継がれます。

**配置**

```
{workspace}/.codex/personas/<name>.md
~/.codex-studio/personas/<name>.md   # 全プロジェクト共有（同名はワークスペース優先）
```

**起動・解除**

```
/persona mentor この関数を新人向けに説明して
/persona clear
```

| 入口 | 挙動 |
|------|------|
| AI パネルの Persona ピッカー | セッション sticky を切替 |
| `/persona <name> …` | sticky 保存 + 当該ターンに適用 |
| `/persona clear`（または `off`） | sticky 解除 |
| 設定 → Personas タブ | 一覧 / 新規 / 編集 / 削除 |
| 設定 → 既定 Persona | 新セッション向けの既定（sticky 未設定時） |
| Teams `role.persona` | 役割ごとの注入 |

同梱例: `strict-reviewer` / `mentor` / `minimal-coder`。

AI パネルでは適用中の Persona・モデル・直近コスト・ツール数が表示されます（Tools タブにも直近ターン要約あり）。

### 5.1 Skills（スラッシュコマンド）

再利用可能な手順をファイルに置き、`/名前` で起動します。

**配置**

```
{workspace}/.codex/skills/<name>/SKILL.md
~/.codex-studio/skills/<name>/SKILL.md   # 全プロジェクト共有（同名はワークスペース優先）
```

**例（このリポジトリ同梱）**

| コマンド | 用途 |
|----------|------|
| `/review` | 変更レビュー |
| `/security` | セキュリティ観点 |
| `/explain` | モジュール説明 |
| `/video-tutorial` | Markdown から解説動画（MP4）を生成 |
| `/presentation` | Markdown からプレゼン資料（PPTX）を生成 |
| `/virtual-company` | 営業・マーケ・法務・技術→社長承認→実装 |

入力欄で `/` と打つと候補が出ます。Ask / Agent どちらでも使えます。

### 5.1.1 動画生成（GenerateVideo）

Markdown / 手順書から解説動画をワークスペース内に生成します（NotebookLM 外注はしません）。

| 項目 | 内容 |
|------|------|
| 入口 | Agent で `/video-tutorial path/to.md`、または Tool `GenerateVideo` |
| 既定モード | **hybrid**（手順=slides+TTS、概念カット=Runway） |
| 出力 | `.codex/video/<slug>/out.mp4` |
| 必須 | `ffmpeg`（PATH または `FFMPEG_PATH`）、OpenAI キー（Director / TTS） |
| 任意 | Runway API キー（設定または `RUNWAYML_API_SECRET`）。無い場合は slides にフォールバック |
| 権限 | 設定のツール権限 **メディア（GenerateVideo / GeneratePresentation）**（既定 ask） |

設定ダイアログに Runway キー・レンダーモード・有効/無効があります。詳細は [動画生成プラン](../12-動画生成プラン.md)。

### 5.1.2 プレゼン生成（GeneratePresentation）

Markdown / 手順書から PPTX プレゼンをワークスペース内に生成します（Canva / Gamma 外注はしません）。

| 項目 | 内容 |
|------|------|
| 入口 | Agent で `/presentation path/to.md`、または Tool `GeneratePresentation` |
| テーマ | `midnight` / `paper` / `forest` / `coral`（設定で既定を変更可） |
| 出力 | `.codex/presentation/<slug>/out.pptx`（+ `deck.json` / `slides/*.svg`） |
| 任意 | OpenAI キー（Director）。無い場合は heuristic で完走 |
| 権限 | 同上 **メディア**（既定 ask） |

設定ダイアログにテーマ・最大枚数・話者ノートがあります。詳細は [プレゼン生成プラン](../13-プレゼン生成プラン.md)。

**SKILL.md の形**

```markdown
---
name: review
description: 候補に出る短い説明
argument-hint: 任意引数のヒント
---

ここに手順を書く
```

### 5.2 プロジェクト常駐コンテキスト

ワークスペース直下にあれば Rules の後に system へ自動注入されます。

| ファイル | 用途 |
|----------|------|
| `CODEX.md` | 推奨 |
| `CLAUDE.md` | Claude Code 互換 |
| `AGENTS.md` | 汎用エージェント向け |

### 5.3 Rules

| 場所 | 用途 |
|------|------|
| `.codex/rules/*.md` | プロジェクト Rules |
| `.cursor/rules/*.{md,mdc}` | Cursor 互換 |
| `~/.codex-studio/rules/*.md` | グローバル |

設定の **Rules** タブからも追加できます。

### 5.4 Compact

- **自動**: 設定の Compact 閾値超過時（Agent 実行中）および Ask の長い履歴
- **手動**: AI Chat の **Compact** ボタン

AI Chat の **Tools** タブでは、セッション中のツール呼び出しログを専用パネルで確認できます。直近ターンのトークン・レイテンシ・推定課金は Chat ヘッダ下に表示されます。

### 5.5 Hooks（イベント駆動）

`.codex/hooks.json` で保存時・Agent 完了時に Shell または Skill を起動できます。

```bash
cp .codex/hooks.example.json .codex/hooks.json
```

主なフィールド:

| フィールド | 内容 |
|------------|------|
| `event` | `onFileSave` / `onAgentComplete` |
| `paths` / `exclude` | glob（保存時） |
| `action` | `{ "type": "shell", "command": "..." }` または `{ "type": "skill", "skill": "review" }` |
| 変数 | `${file}` `${relativePath}` `${workspace}` `${sessionId}` |

再入防止とクールダウン付きです。Main プロセス更新後は `pnpm dev` の再起動が必要です。

### 5.6 Headless CLI

Electron なしで同じ agent-core を実行します。

```bash
# Agent
pnpm cli -- agent "README を要約して" -w .

# 別プロバイダ
pnpm cli -- agent "/review" -w . -p anthropic
pnpm cli -- agent "一覧して" -w . -p ollama -m llama3.2

# JSON 出力
pnpm cli -- agent "…" -w . --json
```

| オプション | 説明 |
|------------|------|
| `-w` | ワークスペース（既定: cwd） |
| `-p` | `openai` / `anthropic` / `ollama` |
| `-m` | モデル ID |
| `--profile` | `readonly`（既定）/ `ask` / `allow` |
| `--yolo` | 全ツール allow |
| `--json` | 結果を JSON |

`codex-studio` 単体は PATH に入りません。`pnpm cli` または `pnpm exec codex-studio` を使ってください。

**注意**: OpenAI で `429 quota` が出た場合は課金・枠を確認するか、`-p anthropic` / `-p ollama` に切り替えてください。

### 5.7 Subagents（Task）

Agent が `Task` ツールで読取専用サブエージェントを並列起動します。

- 子が使えるツール: Read / Grep / Glob のみ
- 入れ子 Task は不可
- 並列数は設定の「並列 Subagent 上限」

チャットでは「認証と IPC を別々に調べてまとめて」のように依頼すると、モデルが複数 Task を使う想定です。

### 5.8 Auto Memory / MemoryAppend

| 方法 | 説明 |
|------|------|
| Auto Memory（設定） | 完了後に `.codex/memory/MEMORY.md` へ要約追記 |
| MemoryAppend ツール | Agent が規約・決定を明示追記（承認対象） |

次回セッションで memory が system に注入されます。

### 5.9 WebSearch

`WebSearch` ツールで公開 Web を検索します（API キー不要）。  
権限カテゴリは **network**（設定で deny 可）。

### 5.10 Agent Teams（ローカル）

複数役割を並列実行し、共有ボードに書いてから統合します。

**配置**

```
.codex/teams/<id>/team.json
.codex/teams/<id>/BOARD.md
```

**サンプル**

| チーム | 用途 |
|--------|------|
| `review-squad` | 正しさ + セキュリティレビュー → 統合 |
| `virtual-company` | 営業・マーケ・法務・技術 → 社長判断 → **人間の社長承認** → **実装** |

各ロールは `skill` / `persona` を指定できます。社長（統合役）にも Persona が注入されます。

**virtual-company の流れ**

1. 営業・マーケ・法務・技術が並列で調査レポート（読取のみ）
2. 社長 AI が判断案を作成（Persona: `ceo`）
3. **社長承認ポップアップ**（承認 / 条件付き承認 / 差し戻し / 見送り）
4. 承認後、実装部がコード変更（Write/Shell は従来どおり個別承認）

```bash
pnpm cli -- team list -w .
pnpm cli -- team run review-squad "IPC と権限をレビュー" -w .
# CLI には承認 UI がないため、virtual-company の実装ステージはスキップされます
```

Agent チャットでは:

```text
/team virtual-company README に導入手順を追加してよいか判断し、承認後は実装まで
/virtual-company 同上（Skill ラッパー）
```

チーム定義は次のいずれかに置けます（ワークスペース優先）:

- `{workspace}/.codex/teams/<id>/team.json`
- `~/.codex-studio/teams/<id>/`（アプリ起動時に同梱チームを自動シード）

`/virtual-company` は Team `virtual-company` のエイリアスです（Skill 経由で Lost しません）。

詳細: [17-バーチャル会社.md](../17-バーチャル会社.md)

Cloud VM / ブラウザ遠隔は **未実装** です（[Phase D ゲート](../09-PhaseD-設計ゲート.md)）。

## 6. 推奨ワークフロー例

### コードレビュー

1. 変更をコミットまたは作業ツリーに残す
2. Agent で `/review` または `/team review-squad 最近の変更をレビュー`
3. 指摘を確認し、必要なら Agent に修正依頼（承認して適用）

### 調査だけ（書込なし）

1. Permission の edit / shell を `deny`、または CLI `--profile readonly`
2. Ask または Agent で質問

### CI / スクリプトから

```bash
export OPENAI_API_KEY=...   # または ANTHROPIC / Ollama
pnpm cli -- agent "テスト失敗の原因を要約" -w . --profile readonly --json
```

## 7. トラブルシューティング

| 症状 | 対処 |
|------|------|
| Agent が動かない | `pnpm dev` を再起動（Main 更新のため） |
| API キーエラー | 設定または環境変数を確認 |
| `429` / quota | 課金・枠を確認。`-p anthropic` や `-p ollama` を試す |
| `tool` must be a response to `tool_calls` | 長い Agent 会話の履歴崩れ。**新しいチャット**を作るか **Compact** 後に再送。アプリを再起動して最新版を使う |
| `codex-studio: command not found` | `pnpm cli -- …` または `pnpm exec codex-studio …` |
| CLI がヘルプだけ出る | `pnpm cli -- agent "…"` のように `--` の後に引数 |
| Hooks が動かない | `.codex/hooks.json` と再起動を確認 |
| 日本語なのに英語で返る | 指示文に日本語を含める（言語検出あり）。アプリ再起動 |
| Ollama 接続失敗 | `ollama serve` と Base URL を確認 |
