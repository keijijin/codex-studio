## 1. 方針

| 方針 | 内容 |
|------|------|
| **再発防止優先** | 個別バグ修正より、同じ抜け道を書けない構造を先に作る |
| **検知を CI に固定** | 実起動・信頼ダイアログ・symlink PoC を人手レビュー依存から外す |
| **段階ゲート** | S0→S4 の順。後段は前段の完了条件を満たしてから本実装に入る |
| **実証還元** | 設計変更はテストと `security-checklist.md` の更新を同一 PR の完了条件とする |
| **公開タイミングで隔離強化** | OS 級 Shell 隔離は一般公開ゲートまで保留 |

---

## 2. フェーズ概要

```
S0 配布ゲート        Electron / 署名 / パッケージ / audit 方針
S1 検出ゲート        実アプリ E2E + tests/security（PoC 移植）
S2 構造ゲート        WorkspaceFs + preview/apply + ESLint
S3 境界ゲート        持ち出し・信頼・env allowlist・preload 制限
S4 体験・保守        巻き戻し・セッション許可・監査/コスト・分割
        │
        └─（将来）一般公開ゲート: OS 級 Shell 隔離
```

## 3. Phase 詳細

### S0: 配布ゲート

**ゴール**: 配布前の既知ブロッカーを洗い出し、受け入れ可能な残件だけを明示する。

| 施策 | 内容 | 完了条件 |
|------|------|----------|
| Electron 追従 | 現行メジャーとの差分・破壊的変更を調査し、更新または据え置き理由を文書化 | 方針が `docs/release.md` または本プラン追記に残る |
| コード署名・公証 | CI Secrets 有無に応じた署名フロー確認 | 未設定時の「署名なし」がチェックリストと一致 |
| パッケージ起動 | `electron-builder` 成果物の起動スモーク | 手順書 + 1 回以上の実測ログ |
| audit | `pnpm audit --prod` の critical/high を分類（修正 / 許容 / 依存更新） | 許容理由つき一覧 |

**非目標**: audit 61 件の全解消。

---

### S1: 検出ゲート

**ゴール**: 「ユニットは緑だがアプリが死ぬ」「PoC だけが知る抜け道」を CI で再現する。

| 施策 | 内容 | 完了条件 |
|------|------|----------|
| E2E 拡張 | `workspace:open`、信頼ダイアログ（E2E 自動信頼フラグの有無を明示）、`window.codex` 存在 | CI 必須ジョブで緑 |
| パッケージ相当ビルド | 可能なら packaged、難しければ `electron-vite build` + 本番 preload 経路 | preload `.cjs` + sandbox で IPC 疎通 |
| PoC 回帰化 | レビュー PoC を `tests/security/` に移植 | 主要シナリオが vitest で固定 |
| PR テンプレ | セキュリティ変更時のチェックリスト（preload / sandbox / path / trust / E2E） | `.github` または CONTRIBUTING に設置 |

**推奨テストカテゴリ（S1）**

1. symlink 親ディレクトリ経由の Write
2. dangling symlink
3. MemoryAppend / BOARD の symlink 脱出
4. Hooks 引用符・部分埋め込み・PowerShell env
5. Team 承認必須
6. Delete のリンク自身削除・マルチルート
7. IPC 送信元完全一致（ユニットまたは統合）

---

### S2: 構造ゲート

**ゴール**: パス検証忘れと承認前実行を、型と lint で阻止する。

| 施策 | 内容 | 完了条件 |
|------|------|----------|
| `WorkspaceFs` | read/write/append/unlink/mkdir の単一 API。内部で常に resolve | ツール・Team board・memory が移行済み |
| ESLint | `packages/tools` / `agent-core` から `fs` / `fs/promises` の直接 import 禁止（テストと WorkspaceFs 実装を除外） | lint が違反を検出 |
| `preview` / `apply` | Tool インターフェースを分離。orchestrator は ask → preview → 承認 → apply | `executeMode` 分岐がツール実装から消える |
| 承認一本化 | `perm === 'ask'` なら必ず承認（`requiresApproval` との AND を廃止または同義化） | Team / MCP / メディアで PoC 緑 |
| マルチルート | `WorkspaceFs` が全 root を試行 | Delete/Read が第2ルートで対称 |

**移行順（推奨）**

1. WorkspaceFs 実装 + ユニット
2. Write / StrReplace / Delete / MemoryAppend / appendBoard
3. Read / Grep 対象パス
4. preview/apply リファクタ
5. ESLint を error に昇格

---

### S3: 境界ゲート

**ゴール**: 信頼境界と情報持ち出し経路をポリシーとして固定する。

| 施策 | 内容 | 完了条件 |
|------|------|----------|
| 未信頼 network | 未信頼ワークスペースでは `network: ask`（または deny） | 設定と実行が一致 |
| 秘密ファイル | `.env*`、鍵、`.agent-env.captured` 等の Read を ask/deny | glob リストが設計書に固定 |
| 信頼ハッシュ | hooks / agent.env / skills 等のハッシュを保存し、変更時に再確認 | 変更検知のユニット + UI 文言 |
| untrust UI | Settings から信頼解除 | 解除後に hooks/agent.env が無効 |
| env allowlist | 除外リストから許可リストへ | PATH（端末同期）等の例外が文書化 |
| preload 制限 | 汎用 `invoke` 廃止、許可チャンネルのみ expose | 未登録チャンネルが呼べない |

---

### S4: 体験・保守

**ゴール**: 安全側に倒したことによる UX 劣化を補い、障害温床の巨大モジュールを分割する。

| 施策 | 内容 | 完了条件 |
|------|------|----------|
| ターン巻き戻し | `.codex-studio/backups` をターン単位で束ねて取り消し | UI から 1 ターン分を戻せる |
| セッション許可 | 「このコマンドをこのセッション許可」 | 承認疲れの緩和を計測（承認回数ログ） |
| MCP 粒度 | サーバー / ツール単位の権限 | 設定 UI + 実行時フィルタ |
| コスト可視化 | Team / Subagent を日次予算に集計 | 画面またはログでロール別表示 |
| 監査ログ UI | Shell・承認の詳細を検索 | 最低限の一覧 + フィルタ |
| モジュール分割 | SettingsDialog / app-store / agent.ts | 行数目標と責務境界を設計書どおり |
| カバレッジ復帰 | agent.ts・IPC を計測対象に戻す | vitest 設定から除外解除 + 最低ライン |
| agent-benchmark 拡張 | ローカルモデル比較に利用 | 実行手順を docs に残す |

## 5. 依存関係

```
S0 ──┬── S1 ── S2 ── S3 ── S4
     │         │
     └─────────┴── 並行可能な調査・文書更新
```

- S1 のセキュリティテストは S2 の受け入れに必須
- S3 の env allowlist は端末同期 UX に影響するため、S4 のセッション許可より先に仕様確定が必要
- S4 の巻き戻しは S2 の書込経路が安定してからが安全

## 7. ロールバック方針

- Feature flag で「厳格 path / 厳格承認」を段階投入可能な場合は flag を使う
- ESLint 禁止は warn → error の二段で入れる
- env allowlist は「未知キーを落とす」挙動を changelog に明記し、1 リリースはログに落としたキーを残す
