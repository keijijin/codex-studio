## 1. 目的

Markdown / リポジトリ文脈から **高品質なプレゼン資料（PPTX）** を Codex Studio 内で生成できるようにする。

Gamma / Canva を「テンプレ量・共同編集 UI」で正面から代替するのではなく、**エージェント駆動の構成・正確さ・再生成・リポジトリ連携**で凌駕する。

### 方針（決定事項）

| 決定 | 内容 |
|------|------|
| 外部 Canva / Gamma API 外注 | **しない**（本線にしない） |
| 第1成果物 | **PPTX**（PowerPoint / Keynote / Google スライド互換） |
| 補助成果物 | `deck.json` + スライド SVG プレビュー |
| デザイン | **自前テーマ**（キュレート済み 4 系統）。外部デザイン API に依存しない |
| 入口 | Skill `/presentation` + Tool `GeneratePresentation` |
| 重処理 | Electron 非依存の `packages/media`（動画と同居） |
| 差別化 | コード実埋め込み・話者ノート・動画パイプラインとの deck 共用（V2） |

### 非目標（当面）

- Canva / Gamma 相当の WYSIWYG 編集 UI
- ブランドキットのクラウド同期・共同編集
- 画像生成 API への丸投げレイアウト
- MCP 経由の公開

## 2. パイプライン

```
入力: Markdown パス / プロンプト / オプション
        ↓
① Deck Director（既存 LLM・監督プロンプト）
   → deck.json
     - title, themeId
     - slides[]: layout, title, bullets, code, quote, notes, …
        ↓
② Render
   - PPTX（pptxgenjs）← 本線
   - SVG プレビュー（各スライド）← プレビュー / 動画再利用の種
        ↓
③ 出力
   → .codex/presentation/<slug>/
        deck.json
        out.pptx
        slides/01.svg …
```

### deck.json 例

```json
{
  "title": "RLS 入門",
  "themeId": "midnight",
  "slides": [
    {
      "id": "01",
      "layout": "title",
      "title": "RLS 入門",
      "subtitle": "テナント分離を行レベルで実現する",
      "notes": "導入。聴衆はバックエンドエンジニア想定。"
    },
    {
      "id": "02",
      "layout": "bullets",
      "title": "なぜ RLS か",
      "bullets": [
        "アプリ層だけのフィルタは漏れやすい",
        "DB が最後の防衛線になる",
        "ポリシーを一箇所で管理できる"
      ],
      "notes": "3 点だけ。詳細は次スライド。"
    },
    {
      "id": "03",
      "layout": "code",
      "title": "ポリシー例",
      "code": "CREATE POLICY tenant_isolation ON orders\n  USING (tenant_id = current_setting('app.tenant_id'));",
      "codeLanguage": "sql",
      "notes": "コードはソースから抜き出した実例であること。"
    },
    {
      "id": "04",
      "layout": "closing",
      "title": "次の一歩",
      "bullets": ["マイグレーションで ENABLE", "結合テストで漏洩を確認"],
      "notes": "Q&A へ。"
    }
  ]
}
```

## 3. スライドレイアウト

| layout | 用途 | 必須フィールド |
|--------|------|----------------|
| `title` | 表紙 | title, subtitle? |
| `section` | 章扉 | title, subtitle? |
| `bullets` | 箇条書き | title, bullets[]（最大 7） |
| `two_column` | 対比 | title, leftBullets[], rightBullets[], leftTitle?, rightTitle? |
| `code` | コード | title, code, codeLanguage? |
| `quote` | 引用・要点 | title?, quote |
| `closing` | まとめ / CTA | title, bullets? |

**品質ルール（Director / ヒューリスティック共通）**

- 1 スライド 1 メッセージ。箇条書きは **7 行以下**、1 行は短く
- コード・パス・コマンドは必ず `code`（幻覚禁止。ソースに無いコードは作らない）
- 話者ノート `notes` を可能な限り付与（発表用）
- 日本語ソースなら日本語、英語なら英語

---

## 4. テーマ

| themeId | トーン | 用途イメージ |
|---------|--------|--------------|
| `midnight` | ダーク・シアンアクセント | 技術トーク既定 |
| `paper` | ライト・インク | 文書・社内共有 |
| `forest` | ダークグリーン | プロダクト / サステナ |
| `coral` | ライト・コーラル | ピッチ・提案 |

テーマは色・タイポのトークンのみ。レイアウト骨格は共通（一貫性 > 派手さ）。

## 5. アーキテクチャ

| レイヤー | パス | 役割 |
|----------|------|------|
| Skill | `.codex/skills/presentation/SKILL.md` | 使い方・品質基準 |
| Tool | `packages/tools/src/tools/generate-presentation.ts` | Agent から起動 |
| Media | `packages/media/` | Director / deck / PPTX / SVG |
| Shared | `packages/shared` | `presentation` 設定・権限 `media` |
| CLI | `pnpm cli -- presentation generate …`（V2） | CI / 無人再生成 |

```
UI Agent / CLI
    → GeneratePresentation Tool
        → packages/media
            → DeckDirector (LLM adapters / heuristic)
            → PptxExporter (pptxgenjs)
            → SvgSlideRenderer
```

動画の `Shotlist` とは別型（`Deck`）とするが、V2 で `Deck → Shotlist` 変換を足し、同一資料から MP4 も出せるようにする。

---

## 6. 設定スキーマ

`AppSettings.presentation`（新規）:

```ts
presentation: {
  enabled: boolean
  themeId: 'midnight' | 'paper' | 'forest' | 'coral'
  maxSlides: number          // 既定 16
  includeNotes: boolean      // 話者ノートを PPTX に含める
  outputDir: string          // 相対: .codex/presentation
}
```

権限: 既存カテゴリ **`media`**。`GeneratePresentation` は `GenerateVideo` と同様に既定 `ask`。

## 7. フェーズ

### V1 — MVP（本ドキュメント実装対象）

| # | 成果物 | 完了条件 |
|---|--------|----------|
| V1-1 | `Deck` 型 + heuristic / parse / normalize | 単体テストで JSON 検証 |
| V1-2 | Deck Director（LLM 1 回、失敗時 heuristic） | 代表 MD からスライド列が生成される |
| V1-3 | PPTX エクスポート（テーマ 4 種） | `out.pptx` が開ける |
| V1-4 | SVG プレビュー | `slides/*.svg` が出力される |
| V1-5 | `GeneratePresentation` Tool + Skill | Agent から `.codex/presentation/<slug>/` |
| V1-6 | 設定・権限・マニュアル追記 | キー無しでも heuristic で完走可 |

**受け入れ**: 短い Markdown（〜800 語）から 5–12 枚の PPTX が生成される。OpenAI キー無しでも heuristic で完走。

### V2 — 実用

- CLI `presentation generate`
- プレビュー UI（SVG / 簡易 HTML）
- `Deck → Shotlist` で動画との dual export
- ブランド色の上書き（accent / logo path）

### V3 — 品質

- 図表（mermaid → SVG）埋め込み
- 画像アセット配置ルール
- インライン微修正（「3 枚目だけ差し替え」Tool）

## 8. Gamma / Canva との差別化（成功の定義）

| 観点 | Gamma / Canva | Codex Studio（目指す姿） |
|------|---------------|--------------------------|
| 入力 | プロンプト / 貼り付け | **リポジトリ・手順書・実コード** |
| 正確さ | 生成テキスト中心 | **ソース根拠のコード・手順** |
| 反復 | UI 上の手直し | **Agent 会話で差し替え再生成** |
| 連携 | デザインツール内 | **動画・ドキュメントと同じワークスペース** |
| 編集 UI | 強い | V1 では弱くてよい（PPTX を外部で開く） |

「凌駕」の計測はテンプレ数ではなく、**(1) 実コードが正しい (2) 構成が発表可能 (3) 再実行で再現できる** の 3 点。

---

## 9. リスクと緩和

| リスク | 緩和 |
|--------|------|
| LLM がコードを捏造 | Director ルールで code はソース抜粋のみ。heuristic はフェンス内をそのまま使用 |
| スライド過多 | `maxSlides` + normalize で打ち切り |
| 見た目が素人っぽい | キュレートテーマ + 余白・タイポ規約をコードに固定 |
| pptxgenjs 依存 | media パッケージに閉じ込め、失敗時は SVG + deck.json は残す |
| キー漏洩 | API キーは既存 models 経路のみ（presentation に独自キーは持たない） |

## 10. 成功指標

- Agent: `/presentation path/to.md` で PPTX がワークスペース内に残る
- OpenAI キー無しでも heuristic で完走
- 同一入力で同じ `slug` 配下に成果物が揃う
- Canva / Gamma への依存ゼロ
