## 1. 目的

一つの案件について **営業・マーケティング・法務・技術** が並列レポートし、**社長（AI）**が判断案を出し、**人間の社長承認**のあと **実装部**が責任を持って実行する。

```
案件
  ├─ 営業部 (sales-dept)             ──┐
  ├─ マーケティング部 (marketing-dept) ┼→ BOARD → 社長 AI (ceo)
  ├─ 法務部 (legal-dept)             ──┤         │
  └─ 技術部 (eng-dept)               ──┘         ▼
                                      人間の社長承認 UI
                                                 │ approve / conditional
                                                 ▼
                                      実装部 (eng-executor) → コード変更
```

## 2. 多段パイプライン

| Stage | 内容 |
|-------|------|
| `research` | 営業・マーケ・法務・技術を並列実行（読取のみ） |
| `decide` | 社長 Persona で統合・判断案（読取のみ） |
| `await_approval` | ポップアップで人間が承認 / 条件付き / 差し戻し / 見送り |
| `execute` | 実装部が高権限ツールで変更（Write/Shell は従来の承認ダイアログ） |
| `done` / `cancelled` | 完了または中止 |

`team.json` の `pipeline.requireCeoApproval` / `executeAfterApprove` で制御。

## 3. 使い方

ワークスペースに `.codex/teams` が無くても、アプリは `~/.codex-studio/teams` へ同梱チームをシードします。別フォルダを開いていても `virtual-company` が使えます。

```text
/team virtual-company README に導入手順セクションを追加してよいか判断し、承認後は実装まで
```

または `/virtual-company <案件>`（Team 直接起動）。

CLI（承認 UI なし → 実装はスキップ）:

```bash
pnpm cli -- team run virtual-company "案件の説明" -w .
```

## 4. 同梱

| 種別 | 内容 |
|------|------|
| Team | `.codex/teams/virtual-company/` |
| Personas | sales-dept / marketing-dept / legal-dept / eng-dept / ceo / eng-executor |
| Skill | `/virtual-company` |

## 5. 安全

- 調査・判断段階は読取のみ
- 実装は人間の社長承認後のみ
- 実装中のファイル編集・Shell は個別のツール承認が必要（YOLO でない限り）
- 差し戻し / 見送りでは実装しない
